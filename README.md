# ⚛️ React Frontend Challenge

Welcome to the React Frontend Challenge!

In this project, you are given a complete HTML template located inside the `public` folder.

Your task is to convert this template into a well-structured and functional **React application**.

The goal is not only to make the website look like the original template. You should also demonstrate your understanding of **React, component-based architecture, clean code, responsive design, and UI/UX principles**.

---

## 📅 Deadline

**October 24, 2026**

The completed project must be submitted before the deadline.

Make sure you manage your time carefully. Do not leave the entire project for the last day.

---

## 🎯 Main Objective

Convert the provided HTML template into a proper React application.

The final project should:

- Use React correctly
- Be divided into reusable components
- Have a clean and understandable project structure
- Be responsive on different screen sizes
- Keep the main design and identity of the original template
- Improve UI/UX where necessary
- Have clean and readable code
- Work without major errors

---

## 📁 Template Location

The original HTML template is available inside:

```text
public/
```

Before starting development, carefully review the entire template.

Understand its:

- Pages
- Sections
- Layout
- Navigation
- Forms
- Cards
- Buttons
- Images and assets
- Responsive behavior
- Interactive elements

Do not start by simply copying everything into React.

First, analyze the template and decide how it should be divided into components.

---

## 🧩 Component-Based Development

One of the most important parts of this challenge is **componentization**.

You should identify repeated or independent parts of the UI and convert them into reusable React components.

For example:

```text
Header
Navbar
Hero
Sidebar
ProductCard
Section
Button
Modal
Footer
```

These are only examples.

You are responsible for deciding which parts should become components.

Avoid creating one very large component containing the entire page.

At the same time, do not create unnecessary components for every small HTML element.

Your component structure should have a clear reason behind it.

---

## 🔄 Use React Properly

This project should not be just HTML files moved into a React project.

Use React features where they make sense.

Depending on the template, this may include:

- Components
- Props
- State
- Event handling
- Conditional rendering
- Rendering lists with `map()`
- Forms
- Reusable UI elements

For example, if several cards have the same structure, avoid manually repeating the same JSX many times.

Instead, think about creating reusable components and rendering them from data.

---

## 📱 Responsive Design

The final project must work correctly on different screen sizes.

At minimum, check your project on:

- Desktop
- Tablet
- Mobile

Elements should not overlap, disappear incorrectly, or break the layout on smaller screens.

Responsive design is part of the challenge and will be considered during evaluation.

---

## 🎨 UI/UX Improvements Are Allowed

You are **allowed and encouraged to improve the original template**.

If you find something that can be improved from a UI or UX perspective, you may change it.

For example, you may improve:

- Spacing
- Typography
- Button design
- Navigation
- Mobile experience
- Form usability
- Visual hierarchy
- Colors and contrast
- Card layouts
- Hover states
- Empty states
- User feedback
- Section organization
- Accessibility

However, changes should not be random.

### Every major UI/UX change should have a logical reason.

You should be able to explain:

> What was the problem?

> What did you change?

> Why is your solution better for the user?

Creative improvements are welcome, but they should improve the experience rather than simply make the project different from the original template.

---

## 🧠 Think Like a Frontend Developer

Do not only ask:

> "How can I make this look like the template?"

Also ask:

> "How should this application be structured?"

> "Can this component be reused?"

> "Is this easy to maintain?"

> "Does this work properly on mobile?"

> "Is this interaction clear for the user?"

> "Can another developer easily understand my code?"

This challenge is about both **development and problem-solving**.

---

## 🧹 Code Quality

Your code should be:

- Clean
- Readable
- Organized
- Consistent
- Easy to understand

Avoid:

- Very large components
- Unnecessary duplicated code
- Repeated JSX that could be reusable
- Unused files
- Unused variables
- Unclear variable names
- Random folder structures
- Large amounts of commented-out code

Good naming is important.

Prefer:

```js
ProductCard
handleSubmit
isMenuOpen
products
userProfile
```

instead of unclear names such as:

```js
x
data2
test
abc
func1
```

---

## 🔗 Navigation & Interactions

Interactive parts of the original template should actually work.

Depending on the project, this may include:

- Navigation
- Mobile menu
- Dropdowns
- Tabs
- Modals
- Forms
- Search
- Filters
- Buttons
- Accordions
- Other interactive elements

Do not keep an element purely visual if it is clearly supposed to have an interaction.

You may use AI tools as an assistant.

- Learn a concept

If you make important changes to the original UI/UX, add a section to your project documentation called:

```text

```

Briefly explain your important changes.

Example:

```text

Problem:

Solution:
```
